# Harness eval pilot, 2026-11-25

Runner and design: [README](README.md). Raw data: [`pilot-2026-11-25/runs.jsonl`](pilot-2026-11-25/runs.jsonl) (54 records), runner report: [`pilot-2026-11-25/report.md`](pilot-2026-11-25/report.md). The 6 MB of raw streams are not in git.

## Conclusion

- **Q1, does odd-claude improve outcomes vs plain Claude Code?** No measurable difference at this difficulty. Every arm passed 18/18 hidden-test runs (ceiling effect), so this pilot cannot detect an outcome difference, in either direction.
- **Q2, does full delegation pay off its token cost?** Not on these tasks. `coord-on` cost 30% more than `coord-off` and 81% more than `none` (tokens +65% and +139%) with the same 100% pass rate. At this difficulty it does not pay off.
- Both answers are bounded by n=3 per cell and tasks that a plain agent solves easily (see Caveats).

- Validity: 54/54 runs finished, 0 `invalid` (plugin, output style and delegation mode matched each arm), all status `ok`.
- Isolation, re-verified after the pilot: the real `~/.claude/settings.json` sha1 is unchanged, the `plugins/` and `plugins/data` directory lists are unchanged, nothing new in them except live interactive sessions' `sessions/`/`status` files, no leftover temp workspaces.

## Outlier

`inventory-orders-bug.coord-off.2`: wall 554 s while the session's own `duration_ms` was 108 s and `duration_api_ms` 106 s (cost 0.334, normal). From the stream timestamps: two idle gaps (84 s and 387 s) between tool results and the next model message, then 6 `api_retry` events (`error: unknown`, delays 0.6 to 19 s) before the final answer. It is an API or network stall, not agent behavior, and says nothing about the arm. Without it `coord-off` wall is 61.2 s mean / 23.0 s stdev. The runner's `wall_ms` includes such stalls; `duration_ms` does not.

## Visible tests edited

The field `visible_tests_modified` is true when a shipped test file was changed or removed (new files do not count, but edits that add tests to an existing file do). So it is not a cheating signal by itself. Checked 3 streams (`range-merge-bug.none.1`, `csv-quoted-fields.none.2`, `ledger-money.coord-off.1`): each added regression tests to a visible test file (one rewrote the file with new tests); none weakened an assertion. The other 35 flagged runs are unverified; hidden tests pass in all of them. Counts per arm: none 12, coord-on 15, coord-off 11 of 18, concentrated in the bugfix and `csv-quoted-fields` tasks.

## Caveats

- n=3 per cell, 18 per arm. Stdev is large relative to the arm differences in wall time; the cost and token gaps are larger than the stdevs but are still one pilot.
- Ceiling effect: 100% pass everywhere. The pilot measures cost and time at equal outcome, not quality.
- Tasks are small or medium, single-session, with clear prompts and visible tests. They favor the plain agent; harness discipline (specs, review, memory) has little to add.
- Engram is absent: odd-claude was measured without its memory.
- Cost is API-equivalent from `total_cost_usd`; auth was a subscription, so no money was billed.
- One main model (opus), one CLI version (2.1.332), one prompt per task. Runs are nondeterministic.
- Pass/fail only; no review of diff quality or test quality.

## Next steps (recommendations, not done)

1. Harder tasks where discipline matters: ambiguous specs, multi-file changes with traps, regressions in untouched code, long-horizon work across sessions.
2. Outcome metrics beyond pass/fail: hidden regression tests on untouched behavior, diff size, test quality, whether visible tests were weakened (diff-based, not hash-based).
3. More trials per cell to bound variance.
4. An arm with engram installed, to measure odd-claude with its memory.
