# Python v10 Phase 3: review engine and MCP server
Objective: port the v9 review engine (`plugins/odd-claude/src/review/`, ~8.6k lines), the odd-review MCP server (`src/mcp/`, ~0.8k) and the `review-mode` CLI to Python at behavioral parity, as Phase 3 of `docs/roadmap-v10-python.md` defines. Branch: `feat/py-review` (base `f7a7c4f`). Delivery: `single-pr` (ODD default; one PR per phase as in Phases 0-2). Runner: `uv run pytest`; contract suite `cd plugins/odd-claude && npm run test:contract` and `ODD_IMPL=py npm run test:contract`; `npm test` stays green.

## Specs
- **S1** Roadmap Phase 3 goal, verbatim: "Review lifecycle, the odd-review MCP server and the `review-mode` CLI in Python." Scope, verbatim: "Pure state machine, revision-CAS store, consent binding and drift, forecast, capture, acknowledgement, 10 tools with identical names and input schemas (contract item 3), restricted validation and argument coercion as v9. The `review-mode` CLI (a command hook contract tests spawn). Starts from the merged `autonomous-review` state (PR #68, v9.2.0)." Assumptions (parent): (a) one Python module per v9 file: `src/odd_claude/review/<module>.py` for `src/review/*.ts`, `src/odd_claude/mcp/<module>.py` for `src/mcp/*.ts`, `src/odd_claude/cli/review_mode.py` for `src/cli/review-mode.ts`; same public functions in snake_case, constants, messages and exit codes; (b) each v9 spec of these files is ported to `tests/review/`, `tests/mcp/` or `tests/cli/` with at least as many cases as its v9 `test(` count in L5; (c) the Phase 2 lib modules and `src/odd_claude/lib/js.py` are reused, never re-implemented; (d) inherited from Phase 2 S7 (`odd/tasks/py-core-lib.md`, the method that found the missing RED and Unicode gaps there): every exported function gets a differential test against the compiled v9 module through the oracle (`tests/lib/v9_oracle.py`, extended to `dist/review/` and `dist/mcp/`); (e) inherited from Phase 2 S1(d): runtime uses only the standard library and Pydantic, no new dependency. Check: for each v9 file a Python module and a ported test file exist; `uv run pytest` exits 0; every `test_diff_*` of this phase passes.
- **S2** Exit criterion, verbatim: "MCP contract and conformance suites pass with `ODD_IMPL=py`." Decision D2 context (roadmap section 2): hooks come in Phase 4. Human decision (L6): "Sí, diferir a F4 (Recommended)" (option text: "Fase 3 cierra con todo lo demás en verde con ODD_IMPL=py; esos 8 tests quedan listados en el Log y son criterio de salida de la Fase 4."). So contract tests that also spawn `hook-runner` (the `lifecycle.spec.ts` scenarios and `crash.spec.ts` "kill -9 BETWEEN the receipt write and the burn" and "the receipt check is what makes `consumed`") cannot pass before Phase 4; under `ODD_IMPL=py` they must fail only with the missing-entry message for `hook-runner`, and they become Phase 4 exit checks. The conformance part: the `src/conformance/*.spec.ts` files mapped to phase 3 in `docs/contracts/test-mapping.md` (MCP and review texts and canonical JSON, e.g. `contract.spec.ts`, `tools-guidance.spec.ts`, `standing-consent.spec.ts`, `escalation.spec.ts`; the writer lists the exact set) are ported to `tests/conformance/` asserting the same against the Python modules. Check: `uv run pytest tests/conformance` exits 0; `ODD_IMPL=py npm run test:contract` passes every test whose entries are all ported (review-server, review-mode, plus the earlier ones), and every failing test names only `hook-runner` (or another entry of a later phase) as missing; the list of deferred tests is recorded in the Log.
- **S3** Exit criterion, verbatim: "Tool names and input schemas match v9 exactly (diffed from `tools/list`)." Check: a test runs `tools/list` against the v9 server (`node plugins/odd-claude/dist/mcp/review-server.js`) and the Python server and asserts the JSON is identical (names, descriptions, input schemas, order).
- **S4** Exit criterion, verbatim: "A review transaction written by TS is readable by Python and the reverse." Check: a cross-implementation test drives one lineage start to approved and burned through the v9 server and reads it with the Python store (status and inspect), then the same with Python writing and v9 reading; the `test-fixtures/contracts/review-store/` fixture is read by Python without a schema error.
- **S5** Exit criterion, verbatim: "`review-mode` contract tests pass with `ODD_IMPL=py`." Check: the contract tests that spawn `review-mode` (`stop.spec.ts` uses it through `setReviewMode`; `persisted-formats.spec.ts` plugin-state) pass with `ODD_IMPL=py` except where they also need `hook-runner` (S2 deferral).
- **S6** Roadmap Phase 3 risk, verbatim: "Items 1, 3, 4." (the ODD numbering in roadmap section 6: 1 persisted data, 3 consumed contracts, 4 concurrency). Check: an independent odd-verify runs on the store/lock/CAS unit and on the MCP server unit; blockers fixed and rechecked; findings in the Log.
