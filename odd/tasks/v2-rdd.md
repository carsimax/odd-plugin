# v2 native RDD in TypeScript (Phase 8, RDD part)
Goal: reimplement the review engine (state machine, authority store, reviewers, MCP, Stop settle reminder, delivery gate) natively in TypeScript with odd-claude names, using upstream gentle-ai only as a read-only reference. Branch: `feat/v2-rdd`.
Runner: `node:test` via `npm test` inside `plugins/odd-claude` + `npm run check` + `claude plugin validate` / `claude plugin test`. Engine map: `docs/research/rdd-engine-map.md`.

## Specs

### S1 Roadmap Phase 8 (docs/roadmap.md, "### Phase 8: v2, native RDD + peer orchestrators")

- **Goal:** the explicit **v2** milestone: the portable items deliberately left out of v1 (native RDD and inter-session peers), planned for after v1 ships. These are the only v2 scope.
- **Matrix IDs:** R03, R07, R29, R30, R31, R32, R33, R74, A39, A40, A47, A48
- **Deliverables:** (native RDD, v2; Q4 option A or B reopened when v2 starts) MCP server with `odd_review`, `odd_review_run`, `odd_review_capture`, `odd_review_capture_group`, `odd_review_scope`, `odd_phase` (R29), candidate views (R33), request-context placement (R74), contract fragment injection (R03), `contracts/review-integration/` and `contracts/provider-mirror/` (A47, A48), `/odd-claude:rdd`, `/odd-claude:review-mode`, `/odd-claude:review-session-permission` (R30), Stop hook `odd-settle-nudge` (R31), publication gate tied to review approval `odd-delivery-gate` (R32), skills `provider-defect-report`, `rdd-defect-workflow` (A39, A40). (Peers) `odd_orchestrator_*` tools via a channel chosen then, `$.store` or MCP channels (R07).
- **Dependencies / gates:** v1 shipped; at v2 start, a decision on the review engine (Q4 option A or B) and on the peer channel (`$.store` vs MCP channels, Q5), Q1 if `$.store`.
- **Exit criteria:** per item when promoted: a full native review run (scope → four reviewers → capture → verdict), delivery gate blocking `git push` / `gh pr` on a failing preflight, contract schema validation; two sessions exchange a message with a grant before delivery; or the item is formally dropped (moved to out of scope).
- **Effort:** 3 S (R74, A39, A40) + 6 M (R03, R30, R31, R32, A47, A48) + 3 L (R07, R29, R33).
- **Risk:** high: external binary or the largest TS port (contracts, drift), and a preview channel for peers. Not part of the v1 parity claim (v2 scope).

### S4 Design constraints (from `docs/research/rdd-engine-map.md`)

- Own namespace: `<git-common-dir>/odd-plugin/review-transactions/v2/<lineage>/…` (plus `odd-plugin/` lock files); never read or write the gentle-ai authority, nor the external `odd-claude` CLI tree (`<git-common-dir>/odd-claude/review-transactions/v2`, see L5). Supersedes the `odd-claude/` path in the previous S3 item.
- Hash domains: `"odd-claude.<domain>/v<N>\x00"` + payload.
- ONE canonical JSON (sorted keys), pinned by test vectors.
- Reviewers run as isolated `claude -p` children with the upstream flags (`--print --output-format text --tools "" --permission-mode dontAsk --no-session-persistence --setting-sources "" --system-prompt <isolated reviewer>`, optional `--model`/`--effort`, never `--bare`).
- MCP tools: `review_assess`, `review_inspect`, `review_start`, `review_status`, `review_answer_consent`, `review_capture`, `review_capture_group`, `review_acknowledge_approved`, `review_run`, exposed as `odd_review*` names; final naming decided in U15.
- Blocking only from the delivery gate (PreToolUse Bash) and the Stop settle reminder, and only when RDD is on; an RDD mode switch turns both off.
- No telemetry.
- Node has no `flock`: directory lock with an owner token and a bounded wait.
