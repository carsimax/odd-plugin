Human decision on the suite language (L3): "TS node:test (Recommended)". The black-box specs are the 16 listed in `spikes/py-06-contract-harness/README.md` (3 pure, 13 mixed). Assumptions (parent): (a) one resolver module `plugins/odd-claude/src/contract/impl.testkit.ts` is the only place that maps `ODD_IMPL` to entry commands (CLI by name, hook runner, MCP review server, statusline, release scripts); (b) contract tests live under `plugins/odd-claude/src/contract/`, and each black-box test of the 16 specs moves there; in-process tests of the mixed specs stay in their current files; (c) (parent assumption, needed so the same files can drive a Python implementation; not requested by the human) contract files and the testkits they use import no product module (only `node:*` and other `src/contract/*.testkit.ts`); setup that used product internals becomes files on disk, fixtures, or calls through an entry command; (d) `ODD_IMPL` defaults to `ts`; `ODD_IMPL=py` fails at the resolver with a message naming the missing entry until a Python entry exists; (e) the run prints the implementation in use, as the positive control the spike asked for. Check: `npm run test:contract` exits 0 and prints `ODD_IMPL=ts`; `ODD_IMPL=py npm run test:contract` exits non-zero and every failure names a missing Python entry; a static test asserts no file under `src/contract/` imports a path outside `src/contract/` other than `node:*`.
- **S2** Roadmap Phase 1 scope item, verbatim: "Document every persisted format as a frozen contract, with fixtures captured from the TS implementation."
