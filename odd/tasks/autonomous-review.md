# Autonomous review and single-PR delivery
Objective: make `single-pr` the ODD default delivery and let ordinary review (RDD) iterate autonomously up to 3 passes under a per-feature standing consent. Branch: `feat/autonomous-review` (base `d786321`). Delivery: `single-pr`. Runner: `cd plugins/odd-claude && npm test` (plus `npm run check`); `dist/` is tracked and rebuilt by `npm test`.

## Specs
- **S1** "Quiero que el trabajo final siempre llege a github en una sola pr, todo lo demas podemos dividir el trabajo en local como venimos trabjandolo". Agreed shape (L3, point 1): "El documento de cada feature ya tiene un campo de estrategia de entrega; le añadimos `single-pr` (el concepto viene de gentle-ai) y lo usamos por defecto. El trabajo sigue en commits locales por unidad." So: the ODD default delivery strategy becomes `single-pr` (today `ask-on-risk`); work-unit commits stay local (~400-line planning heuristic unchanged); `ask-on-risk`, `auto-chain` and `exception-ok` remain available when the user picks them; under the default no chain menu is asked. Every place that names the default is updated consistently. Check: no text in `plugins/odd-claude` still names `ask-on-risk` as the default; a conformance test asserts `single-pr` is the default in `rules/odd-tracking.md`.
- **S2** "que el rdd itere de forma autonoma, es decir hasta 3 rondas de rdd antes de comit". Agreed shape (L3, point 3): "RDD autónomo hasta 3 pasadas (1 revisión + 2 correcciones)" and "Solo un BLOCKER/CRITICAL causado por el cambio abre otra ronda; un WARNING no la abre." So: the review engine allows up to 2 correction attempts per lineage (3 review passes); the trigger for a correction stays the existing one (candidate-caused BLOCKER/CRITICAL); a third pass that still has blocking findings escalates (no fourth pass). Existing persisted review-state records (attempts 0 or 1) stay readable. Assumption: each correction keeps the existing per-correction changed-line budget rule. Check: tests through the public engine/MCP interface show a second correction is accepted, a third is refused, and blocking findings after the second correction escalate.
- **S3** L3, point 3: "Si tras 3 pasadas sigue habiendo hallazgos graves, **no hay commit** y te pregunto." So: ODD text states that an escalated review blocks that work-unit commit and the parent asks the human. Check: the rule text says so.
- **S4** L4: consent "En la regla de ODD (Recommended)": "Te pregunto una vez por feature y registro tu respuesta literal en el Log del documento de la feature. Después respondo yo el consentimiento y el pronóstico de cada pasada de esa rama. El motor solo cambia el límite de rondas." So: for a tracked (large) feature, the parent asks once (AskUserQuestion) for standing RDD consent covering that feature branch's work-unit commits, up to 3 passes each; records the human's verbatim answer in the feature document `## Log`; then answers `review_answer_consent` and acknowledges reviewer-run forecasts itself for that branch's candidates only. Without a recorded standing consent the current per-run relay applies unchanged. A decline, or a candidate outside that branch, falls back to per-run relay. The engine's consent mechanics are not changed; only the guidance texts (MCP server instructions, tool descriptions, Stop hook text, ODD rules) are. Check: those texts state the standing-consent exception consistently and their tests pass.
- **S5** L5: "Mi idea para las tareas es mas bien un paso de odd antes de implementar que con una gente y/o skill que valide las task escritas (servira mas adentante por que tengo planes a futuro  de aprovechar la carpeta odd/)". Agreed shape (L6, "T4 en esta feature (Recommended)"): a new ODD step between Track (5) and Implement (6) for tracked features: first the existing structural lint (`dist/cli/tasks.js`), then a new read-only agent `odd-plan-check` that receives only the feature document (blind: never the parent's reasoning) and checks it against `L1` verbatim for missing, unrequested or misread requirements, `done when` checks that are not observable, tasks not linked to an `S#`, and missing Risk lines. One pass, no loop: the parent fixes the document and asks the human only for a genuine product ambiguity. Agent only, no skill for now. Check: the protocol text names the step; the agent definition exists, is read-only, and is registered wherever agents are enumerated (installer payload, model profiles); `npm test` passes.
