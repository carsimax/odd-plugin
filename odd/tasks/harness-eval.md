# Harness eval (M1 pilot): outcome measurement of odd-claude with real Claude sessions
Objective: a dev-only runner on `claude -p` that runs real coding tasks on fixture repos, grades the end state with hidden tests, and records cost, tokens (subagents included), wall time, subagent launches and pass/fail per arm; then the pilot run and its report. Branch: `feat/harness-eval` (from `main` 83dfda7, release 5.3.0). Delivery: `ask-on-risk`.
Runner: `npm run test:bench` at the repo root (bench dev-only, not in the plugin payload); `npm test` + `npm run check` inside `plugins/odd-claude` only if plugin files change (they should not).

## Specs

- **S1** User request (verbatim): "mandemos ff a main con la 5.3.0 y despues medir"
- **S2** User choices (question tool, verbatim): "Piloto 6 tareas (Recommended)"; "Sin plugin / coord ON / coord OFF (Recommended)"; "Opus 5.5 (Recommended)". Option texts shown (verbatim): "6 tareas (bugfix, feature, refactor; chicas y medianas) x 3 brazos x 3 intentos = 54 corridas. Valida el runner y da una primera lectura antes de invertir en 20 tareas. Costo aproximado USD 20-60 con tope por corrida."; "Responde las dos preguntas clave: ¿odd-claude mejora el resultado frente a Claude Code solo?, y ¿la delegación total compensa su costo en tokens?"; "Es lo que usas a diario; la medición refleja tu uso real. Más caro."
- **S3** Parent design, runner (not user words): TypeScript under `bench/src/eval/`, CLI `npm run eval -- [--tasks a,b] [--arms none,coord-on,coord-off] [--trials 3] [--max-budget-usd 2] [--max-turns 60] [--out <dir>] [--dry-run]`. Per run: fresh `mktemp -d` workspace, copy the task's `repo/`, `git init` + initial commit; spawn `claude -p <prompt> --output-format stream-json --verbose --model opus --permission-mode dontAsk --allowedTools <task list incl. Agent, Read, Edit, Write, Glob, Grep, Bash(node *), Bash(npm *), Bash(git *)> --max-turns N --max-budget-usd B --no-session-persistence --setting-sources ""` with shell `timeout`; never `--bare` (plugin hooks must run). Arms: `none` = no `--plugin-dir`; `coord-on` / `coord-off` = `--plugin-dir plugins/odd-claude` with the plugin's delegation state set to `full` / `organic` in an ISOLATED plugin data dir. The eval must never read or write the user's real plugin state, settings or data dir; verify how Claude Code assigns `CLAUDE_PLUGIN_DATA` to a `--plugin-dir` plugin and isolate it (e.g. a per-run `CLAUDE_CONFIG_DIR` copy that keeps auth, or another documented mechanism); if isolation cannot be proven, stop and report. After exit: copy the task's `hidden/` tests into the workspace, run the task's grade command, record pass/fail; record whether the agent modified the visible tests. From the stream-json `result` message: `total_cost_usd`, tokens summed over `modelUsage` (per model too), `num_turns`/`duration_ms` if present, wall time measured by the runner; subagent launches = top-level `tool_use` named `Agent`/`Task`. Output: `runs.jsonl` (one record per run, schema `odd-claude.eval-run/v1`) and `report.md` per arm: pass rate, mean/median/stdev of cost, tokens, wall time, subagents; per task table. Global budget guard: abort before starting a run when accumulated cost + per-run cap would exceed `--total-budget-usd` (default 70). Unit tests use a fake `claude` binary (reuse the `bench/src/sandbox.ts` pattern) and never call the real model.
- **S4** Parent design, tasks: 6 tasks under `bench/eval-tasks/<id>/` with `task.json` (`id`, `kind` bugfix|feature|refactor, `size` small|medium, `prompt`, `grade` command, `timeout_s`), `repo/` (plain Node ESM JavaScript, zero dependencies, `node --test` visible tests, a README) and `hidden/` (acceptance tests the agent never sees, run with `node --test`). Mix: 2 bugfix, 2 feature, 2 refactor; 3 small, 3 medium (medium = several files, a design choice). Hidden tests check behavior through the public interface, deterministic, no network. Each task's `repo/` must FAIL its hidden tests as shipped and a reference solution (kept out of the repo, applied only in the self-check) must PASS them; the self-check script proves both for every task.
- **S5** Parent design, pilot run and report: after a 1-run smoke per arm (cost reported), run the pilot (6 x 3 x 3) only after the human sees the smoke cost; write `docs/eval/pilot-<date>.md` with the results, the caveats (n=3, variance) and what it says about S2's two questions.
