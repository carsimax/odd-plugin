# odd-skills POC: odd-claude as user-level skills, agents and a coordinator CLAUDE.md (no plugin, no RDD)
Objective: a proof of concept that delivers the ODD workflow without the plugin runtime: a coordinator `CLAUDE.md`, user-level skills that launch the subagents they need with the current default models, agent definitions, and minimal deterministic hooks, installed by a script into a chosen Claude config dir; then measured with the eval runner against no plugin, with Opus and Sonnet as main model. Branch: `feat/odd-skills` (from `feat/harness-eval` 3aff7d5). Delivery: `ask-on-risk`.
Runner: `npm run build:bench && node --test bench/dist/eval/*.spec.js`; installer tests as defined in T3.

## Specs

- **S1** User request (verbatim): "Es que me gustaria eso hacer un poc de una rama en la que todo lo manejemos con skills (odd-skills) y un CLAUDE.md como coordinador, todo odd-claude sin el RDD todo manejado por skills que puedan lanzar los subagentes que necesita basados en los modelos default que tenemos actualmente para cada subagente, al no seer un plugin este POC se puede instalar con un script que modifique directamente en nuestroa instalacion de claude"
- **S2** User choices (question tool, verbatim): "Perfil aislado primero (Recommended)"; "Solo markdown + hooks mínimos (Recommended)"; "Sí, con Opus y con Sonnet (Recommended)". Option texts shown (verbatim): "El script acepta un destino (CLAUDE_CONFIG_DIR). Primero lo instalo en un perfil aparte, lo pruebas con `CLAUDE_CONFIG_DIR=... claude` y lo medimos en el eval; tu ~/.claude no se toca hasta que decidas."; "Skills, agentes y CLAUDE.md, más 1-2 hooks deterministas en settings.json para invariantes (bloquear push/force/reset --hard). Sin MCP, sin RDD, sin Node. Lo más liviano y lo que recomienda Anthropic para reglas que no se negocian."; "odd-skills y sin plugin, con Opus y con Sonnet como modelo principal, 3 intentos: 72 corridas, unos USD 25-40. Responde si odd-skills cuesta casi lo mismo que sin plugin y si con Sonnet la disciplina sube el resultado."
- **S3** Parent design, layout (not user words): everything under `odd-skills/` at the repo root: `CLAUDE.md` (coordinator), `skills/<name>/SKILL.md` (+ optional `references/`), `agents/<name>.md`, `hooks/guard.sh`, `install.sh`, `README.md`. Markdown and POSIX shell only (no Node at runtime, no MCP servers, no plugin paths, no `${CLAUDE_PLUGIN_ROOT}`, no `mcp__plugin_odd-claude_*` tools, no review/RDD MCP, no peers, no session-context hooks).
- **S4** Parent design, coordinator `CLAUDE.md`: short (target <= 2.5 KB) and always loaded: identity line, the ODD protocol distilled (authorize: read-only requests stay read-only; explore proportionately; ask one clarification for ambiguous intent; size small/large; small work inline; large or risky work: invoke the `odd` skill), safety rules (no commit/push/PR/merge unless asked, ask before deleting or touching paths outside the repo, no secrets), the `Risk:` line, reply-language rule, and a skill index line (which skill for which situation). Everything else lives in skills loaded on demand.
- **S5** Parent design, skills: port from `plugins/odd-claude/skills/` and the `cards/`/`output-styles/odd.md` rules they depend on, self-contained (cards content inlined into each skill's `references/` where needed). Workflow skill `odd` (large/risky work: feature doc tracking `odd/tasks/<feature>.md`, test-first, delegation: parallel `odd-explore` mapping, `odd-worker` writers with allowed edit surfaces, independent `odd-verify` for high risk, work-unit commits) instructs the Agent call with `model` and `effort` per role. Ported: 4r-review (launches the four `odd-review-*` agents directly with the Agent tool, no review MCP), judgment-day, systematic-debugging, work-unit-commits, branch-pr, chained-pr, receiving-review, comment-writer, issue-creation, cognitive-doc-design, skill-creator, skill-improver, ui-design, tui-design, retro (only if it works without the plugin's Node digest CLI; otherwise drop it and say so). Excluded (plugin runtime or RDD): background-subagents, coordinator, doctor, peers, persona, profiles, scratch, setup, skill-registry, stats, status.
- **S6** Parent design, agents and models: port the 10 agents from `plugins/odd-claude/agents/` with `model:` in frontmatter from the current balanced profile: odd-explore=haiku, odd-worker=sonnet, odd-verify=opus, odd-jd-fix=sonnet, odd-jd-judge-a=opus, odd-jd-judge-b=sonnet, odd-review-readability=sonnet, odd-review-reliability=sonnet, odd-review-resilience=sonnet, odd-review-risk=opus. Remove plugin-only tools (`mcp__plugin_*`); keep `mcp__codegraph__codegraph_explore` and `mcp__engram__mem_save` only as optional tools that are harmless when absent.
- **S7** Parent design, hooks: `hooks/guard.sh` as a `PreToolUse` hook on `Bash` that blocks (exit 2 with a remediation message on stderr) `git push --force`/`-f`/`--force-with-lease`, `git reset --hard`, `--no-verify`, `git branch -D`, `git clean -f`, and `rm -rf` targeting `/`, `~`, `$HOME`, or outside the project dir; allows everything else. Deterministic, POSIX sh + standard tools, reads the hook JSON from stdin.
- **S8** Parent design, installer: `odd-skills/install.sh --target <config-dir> [--uninstall] [--dry-run]`; `--target` is REQUIRED (no default; refuse when missing); it refuses `~/.claude` unless `--i-know-this-is-my-real-config` is also passed. Install: back up every file it changes into `<target>/.odd-skills-backup/<timestamp>/`; copy skills to `<target>/skills/`, agents to `<target>/agents/`, guard to `<target>/odd-skills/hooks/`; add the coordinator to `<target>/CLAUDE.md` between `<!-- odd-skills:begin -->`/`<!-- odd-skills:end -->` markers (create the file if missing, never remove other content); merge the hook into `<target>/settings.json` without dropping existing keys (use `jq` if present; fail clearly if a merge is needed and `jq` is absent); write a manifest of installed paths. Idempotent (re-install replaces its own block/files). `--uninstall` removes exactly the manifest's paths and the marked block and the hook entry, restoring nothing else. Never touches files outside `<target>`.
- **S9** Parent design, eval: new arm `skills` in `bench/src/eval/`: per run, `install.sh --target <private CLAUDE_CONFIG_DIR>` before spawning, no `--plugin-dir`, `--setting-sources user` (so the private config's CLAUDE.md, settings hooks, skills and agents load; the config dir is private so no real user state leaks). Proof fields: `invalid` when the init message lacks the `odd-worker` agent, or (for every arm) when `odd-claude@inline` appears in a non-plugin arm. Measurement: arms `none,skills` × models `opus,sonnet` × 6 hard tasks × 3 trials = 72 runs; report `docs/eval/odd-skills-<date>.md` comparing with the hard-eval arms.
- **S10** User request (verbatim): "si vamos con los 3 puntos", accepting the parent's proposal (verbatim, Spanish): "1. **Arreglar los permisos del eval:** permitir la terminal completa dentro del workspace temporal. [...] 2. **Ajustar odd-skills:** Que en corridas sin supervisión avance con supuestos explícitos en vez de detenerse a preguntar. Que no saque conclusiones generales de un solo comando bloqueado. 3. **Repetir una medición chica** con eso corregido, por ejemplo Sonnet o Haiku sin plugin frente a odd-skills, unos USD 5-10."
- **S11** Parent design, eval permissions: every arm gets the same shell access: plain `Bash` in `--allowedTools` instead of the `Bash(node *)`/`Bash(npm *)`/`Bash(git *)` patterns. If Claude Code documents a native Bash sandbox setting that confines writes to the working directory (check https://code.claude.com/docs/en/settings.md and the sandboxing docs), enable it identically for every arm through `--settings` (merged with the plugin arms' outputStyle JSON) and record `sandboxed: true`; otherwise record `sandboxed: false` and document the exposure in docs/eval/README.md. Record `permission_denials` count per run (from the result message) in the run record and report it per arm.
- **S12** Parent design, odd-skills rules: (a) unattended runs: when no human can answer (non-interactive/headless session, or the request says to proceed), do not stop to ask: proceed with the most conservative reasonable assumption, state each assumption in the final report, and still finish the requested change; (b) a single denied or failing command is not proof a tool is unavailable: retry with a simpler form (one command per call) before concluding, and never claim tests cannot run without trying the test command itself. Both in CLAUDE.md (short) and the `odd` skill.
- **S13** Parent design, re-measurement: arms `none,skills` × models `sonnet,haiku` × 6 hard tasks × 3 trials = 72 runs after a 1-run smoke per arm and model; caps `--max-budget-usd 3 --total-budget-usd 30` per model. Report compares with `docs/eval/odd-skills-2026-11-25.md` (Sonnet) and states how many runs hit permission denials before and after.
- **S14** User question and request (verbatim): "a prori que es mas eficiente descartando rdd odd-claude o odd-skills" then "si arreglalo", accepting the parent's proposal (verbatim, Spanish): "una comparación directa en la misma sesión y con el mismo modelo. Plugin con coordinador OFF contra odd-skills y contra sin plugin, con Sonnet, en las 6 tareas y con la terminal ya arreglada. Serían 54 corridas por unos USD 6-8, y el runner de odd-claude ya tiene las tres configuraciones."
- **S15** Parent design, head-to-head: odd-claude runner gains `--skills-installer <path>` (default unchanged) so the `skills` arm can install the current standalone odd-skills (sibling repo `../odd-skills/install.sh`, at its commit 8fa7abe or later). Run `--arms none,coord-off,skills --model sonnet --trials 3` on bench/eval-tasks-hard (54 runs), caps `--max-budget-usd 3 --total-budget-usd 20`, in one invocation (interleaved arms, same time window), after the odd-skills context-rule measurement finishes. Report `docs/eval/head-to-head-<date>.md`: outcome and cost per arm, odd-skills vs plugin coord-off directly, what the plugin loads per session vs odd-skills, caveats (RDD tools still loaded by the plugin; single-session unattended tasks only).
